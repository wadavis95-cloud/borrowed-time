    How to read this dashboard
    • Capacity includes online racers and lobby guests. The showcase demo runs on the viewing device and uses no race connections or server lobby.
    • CPU, memory and event-loop delays come from this server. They do not measure phone graphics performance.
    • Input RTT is a lightweight application echo; it excludes rendered-frame latency. Snapshot gaps target about 50 ms.
    • HTTP bytes count declared completed response bodies, not partial aborted downloads or transport headers. Race bytes count JSON queued to sockets. Neither is a hosting invoice.
    • Hourly bandwidth projects the latest 30-second average; it is a scenario estimate, not a forecast. Game rates exclude monitoring; a separate card includes dashboard/API response bodies. The hourly projection includes that monitoring output.
    • History lasts up to 30 minutes. The latest minute retains one-second samples; older chart buckets show peak CPU/memory/delay and average rates over roughly ten seconds. Totals reset on restart; client observations expire after 30 minutes or earlier at the 6,000-report cap. No external alerts or durable storage yet. Detecting an outage while this dashboard is closed requires an external health monitor.
    • Signals use provisional sustained thresholds. Calibrate them on the target host before treating them as service guarantees.
    • Browser reporting is capped at 600 reports/minute globally; rejected reports mean coverage is incomplete. Long tasks are unavailable in some browsers.
